# 시안·구현 검수 (design-check)

화면해독.md를 정답지로 놓고, 피그마 시안과 구현 화면이 그 내용을 제대로 담았는지 검수하는 스킬이다.
검수의 목적은 두 가지다. 디자이너·개발자가 **바로 고칠 수 있는 것**을 찾아내고, 고칠 수 없는 것은 **기획이 정해야 할 질문**으로 넘기는 것. 그래서 찾은 것마다 "누가 무엇을 하면 끝나는지"가 보이게 정리한다.

## 준비물

- **기준:** `output/<PDF 파일명>_화면해독.md` (없으면 screen-decode 스킬로 먼저 만든다)
- **시안:** 피그마 파일 URL과 시안 페이지 이름
- **구현:** 구현 화면 파일 경로(예: `prototype/index.html`)나 게시된 URL

셋 중 하나가 없으면 있는 것끼리만 검수하고, 빠진 대상은 보고에 적는다.

## 작업 순서

### 1. 화면해독.md에서 체크리스트 만들기
화면마다 아래를 뽑아 체크리스트로 만든다. 이게 검수의 기준이다.
- UI 요소 번호(1, 2, 3-1 …)와 이름
- 상태 4종: 정의된 것 / `미정의` / `해당 없음`
- 인터랙션: "무엇을 누르면 → 어디로·무엇이"
- 문구 원문 (`⏎` 줄바꿈 포함)
- 기획 질문 번호(꼭 확인 / 나중에 확인). 미정 항목이 시안·구현에서 비어 있는 건 **정상**이므로 미리 표시해 둔다.

### 2. 피그마 시안 읽기
피그마 작업 전에 `figma-use` 스킬을 먼저 불러온다.
- 시안 페이지에서 화면 프레임 목록을 읽는다(보드·화면 이름, 노드 ID).
- 화면마다 **보이는 텍스트 전부**, **인스턴스 이름과 원본 컴포넌트(변형 포함)**, 레이어 이름을 읽어 온다. 숨김 레이어(`visible=false`) 안의 글자는 빼야 한다. 안 그러면 숨긴 헬퍼 문구를 '있다'고 잘못 판단한다.
- 보드 단위 스크린샷을 한 번씩 찍어 겹침·잘림·어색한 줄바꿈을 눈으로 확인한다.
- 지난 검수 이후 다른 사람이 바꾼 부분(사진 교체, 새 컴포넌트 등)이 있으면 기록해 둔다.

### 3. 구현 화면 직접 눌러보기
읽기만으로는 흐름이 끊기는 곳을 못 찾는다. 반드시 실제로 눌러본다.
- **로컬 서버로 연다.** `file://`이나 `data:` 미리보기에서는 브라우저 기록(뒤로가기)과 상대 경로 이미지가 제대로 동작하지 않아 거짓 결과가 나온다. `.claude/launch.json`에 정적 서버(`python3 -m http.server <포트> --directory <폴더>`)를 등록하고 미리보기로 연다. 검수가 끝나면 서버를 끈다.
- 로컬 서버는 문자 인코딩을 지정하지 않아 한글이 깨져 보일 수 있다. 글자로 요소를 찾지 말고 순서·ID·속성으로 찾는다. 글자 대조는 원본 파일이나 게시본에서 한다.
- 화면해독의 인터랙션을 하나씩 스크립트로 눌러 보고 결과를 기록한다. 특히 아래를 꼭 본다.
  - **막다른 화면:** 들어간 뒤 돌아갈 방법이 없는 화면
  - **엉뚱한 연결:** 목록의 다른 항목을 눌러도 같은 상세가 열리는 등
  - **재현 불가 상태:** 팝업·토스트·에러가 정의되어 있는데 구현에서 띄울 방법이 없는 것
  - **경계값:** 최소·최대, 빈 입력, 형식 오류
  - **길어진 내용:** 예시 문구를 늘려서 말줄임·더보기 규칙이 지켜지는지
- 이미지가 실제로 로드되는지(`naturalWidth > 0`), 화면 크기·위치가 시안과 같은지도 숫자로 확인한다.

### 4. 대조하기
- **요소 대조:** 화면해독 요소 번호 × (시안 / 구현) 표. 빠진 게 미정 항목이면 `정상`.
- **상태 4종 대조:** 화면마다 기본·빈·에러·로딩을 시안과 구현에서 각각 확인.
- **문구 대조:** 원문과 한 글자씩 비교. 디자인 시스템 기본값이 원문을 덮어쓰지 않았는지 본다.
- **시안 ↔ 구현 대조:** 기본값(예: 수량), 상태 표시줄·여백 같은 배치, 한쪽에만 있는 상태(예: 스피너).

### 5. 나누고 쓰기
찾은 것마다 하나로 분류한다.
- **고칠 것:** 시안이나 구현이 화면해독과 다르거나, 흐름이 끊기거나, 상태를 볼 수 없는 것
- **맞출 것:** 시안과 구현이 서로 다른 것(어느 쪽이 맞는지 정해야 함)
- **정상:** 기획 미정이라 일부러 비운 것. 목록에는 남기되 고칠 것으로 세지 않는다.

각 항목에는 **화면 · 시안/구현 중 어디 · 내용 · 근거(화면해독 문장 + p.번호) · 제안**을 쓴다. 그리고 고칠 것 중 기획 결정 없이는 못 고치는 것은 제안에 "꼭 확인으로 올리기"라고 적는다.

결과는 `output/<프로젝트명> 시안·구현 검토.md`에 아래 형태로 저장한다.

```markdown
# [프로젝트명] 시안·구현 검토

- 기준: output/…_화면해독.md
- 대상: 피그마 '…' 페이지(화면 N개), 구현 화면 …
- 검토일: YYYY-MM-DD
- 표기: [고칠 것] · [맞출 것] · [정상]

## 한눈에 보기
| 화면 | 화면해독 UI 요소 | 피그마 시안 | 구현 화면 | 고칠 것 · 맞출 것 |

## 고칠 것 · 맞출 것 (N건)
| # | 구분 | 화면 | 내용 | 근거 (화면해독) | 제안 |

## 화면별 상태 점검 (상태 4종)
| 화면 | 기본 | 빈 상태 | 에러 | 로딩 |

## 문구 점검
## 기타
```

### 6. 보고하고, 승인 후 고치기
- 사용자에게 먼저 고치면 좋은 것 몇 가지를 앞에 두고 보고한다. 각 항목을 **눌러봐서 확인한 것**인지 **레이어·코드를 읽어서 찾은 것**인지 구분해서 말한다.
- 고치기는 사용자가 승인한 뒤에 한다. 승인되면:
  - 디자이너·개발자가 고칠 수 있는 건 시안과 구현에서 고친다. 화면해독에 없는 UI(버튼, 문구, 상태)를 새로 만들어 넣지 않는다. 흐름을 이어야 하면 브라우저 뒤로가기처럼 화면에 보이지 않는 방법을 쓴다.
  - 기획이 정해야 하는 건 화면해독.md의 질문 목록에 넣는다. **'디자인 전에 꼭 확인'은 7건을 넘기지 않는다.** 새 질문이 기존 '꼭 확인'보다 디자인을 더 막을 때만 올리고, 그러면 기존 것 중 가장 덜 막는 것을 '나중에 확인'으로 내려 7건을 지킨다. 판단 기준: 화면·탭 전체나 새 상태가 통째로 정해지지 않은 것은 '꼭 확인', 아이콘·버튼 하나, 숫자 하나, 펼침 방식처럼 그려 놓고 나중에 바꿀 수 있는 것은 '나중에 확인'. 목록 화면의 빈 상태와 스피너 노출 기준은 정해지지 않았으면 항상 '꼭 확인'에 둔다.
  - **기존 질문 번호는 바꾸지 않는다.** 그룹을 옮긴 질문은 원래 번호를 다시 쓰고, 새 질문은 그 그룹의 다음 번호를 받는다. 번호가 피그마 메모·리뷰 페이지·구현 화면에 이미 쓰이고 있어서, 번호를 다시 매기면 문서끼리 어긋나기 때문이다. 옮긴 내역은 화면해독.md에 한 줄로 남긴다.
  - 같은 질문이 들어간 곳(피그마 메모 카드, 리뷰 페이지, 구현 화면의 미정 자리)을 함께 갱신한다.
  - 검토 파일에 `## 조치 결과` 표(번호 · 결과 · 한 일)를 추가한다.

## 꼭 지킬 것

1. **직접 확인한 것만 사실로 쓴다.** 흐름·상태는 눌러봐서 확인하고, 못 눌러본 것은 "코드로만 확인"이라고 적는다. 확인하지 않은 걸 됐다고 쓰면 검수의 의미가 없어진다.
2. **미정 항목을 결함으로 세지 않는다.** 기획 미정이라 비운 건 디자이너의 실수가 아니다. `정상`으로 표시해서 진짜 고칠 것이 묻히지 않게 한다.
3. **원문 문구를 기준으로 본다.** 디자인 시스템 기본값이나 구현 편의로 바뀐 문구는 고칠 것이다.
4. **남의 작업을 지우지 않는다.** 누가 넣었는지 모르는 레이어나 파일은 건드리지 않고 보고에만 적는다. 검수용으로 임시로 만든 레이어는 끝나면 지운다.

## 끝내기 전 확인

- [ ] 화면해독의 모든 화면이 '한눈에 보기'와 '상태 4종' 표에 있다.
- [ ] 모든 항목에 근거(화면해독 문장 + p.번호)와 제안이 있다.
- [ ] 구현 화면을 로컬 서버에서 처음부터 끝까지 눌러봤고, 로컬 서버를 껐다.
- [ ] 승인 후 고쳤다면: '꼭 확인'이 7건 이하이고, 화면해독.md·피그마 메모·리뷰 페이지의 질문 수와 번호가 서로 맞고, 검토 파일에 조치 결과가 있다.

보고는 이렇게 끝낸다.

```
검토: output/<프로젝트명> 시안·구현 검토.md
화면: N개 · 고칠 것 A건 · 맞출 것 B건 (정상 C건 제외)
눌러봐서 확인: …  /  레이어·코드로 확인: …
```
